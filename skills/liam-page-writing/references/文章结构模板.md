# 文章结构模板（L2）

> 405 篇全量统计 + 精读样本归纳。体裁按站内分类和字数分布划分，覆盖率 100%。

## 零、通用骨架（所有体裁共用）

1. **无标题图、无摘要、无目录**。正文第一行就是话。站点标题与正文之间不设任何过渡。
2. **85% 有引言**：短引言（2-4 句）42.5%，长引言（>100 字）42.2%，一句话入题 11.9%，直接上小标题 3.5%（全部集中在 2013 年的 LaTeX Tips）。
3. **H2 平均 2.7 个，H2+H3 合计 5.2 个**；107 篇（26%）完全没有小标题，靠段落自然分段。
4. **87.9% 的文章没有「总结/结语/后记」章节**。写完就停。
5. 小标题平均 8.1 字，多为名词短语（「问题描述」「实际效果」「前置知识」），不用问句、不用营销词。

## 一、技术原理解析（Algorithm and Computer Science，109 篇，中位 4283 字）

最长、最正式的一类。特征是**「我们」带着读者从需求推到实现**。

```
一句交代动因（1-3 句）
  例：「此篇我们通过逐步实现线程池，来探讨线程池中的关键技术。」
→ H2「初步讨论」
   → H3「为什么需要 X？」（把需求讲透，常以反问收尾）
   → H3「X 应有哪些特点？」（列成 3-4 条 bullet，每条一句）
→ H2 每个功能模块一节，标题是模块名（「线程安全队列」）
   → 每个模块：先上代码 → 逐行/逐段解读 → 指出这样写的好处与代价
→ （可选）H2「实际效果」/「测试」，贴输出截图
→ 结束。不总结。
```

要点：

- 代码是主体，文字是代码的注释延伸。代码块平均 7.8 个/篇，代码字符占全站 30.8%。
- 每个设计选择都给「为什么不是另一种」：「用 C++ 的语言表达就是说」「modern C++ 的做法应该是…；old-fashion 的做法是…」。
- 常用「我们不妨直接从代码入手，逐步分析」作为分节过渡。

## 二、排错实录（Computer Skills / Jailbreak，88 篇，中位 1500 字）

```
现象描述（2-4 句，必须具体到可复现）
  例：「某次 VSCode 升级之后，我从 macOS 连远端开发机的 Remote-SSH 突然进入了死循环」
→ H2「前置知识」（只在概念需要辨析时出现）
   → 每个概念一个 H3，一段解释 + 一句它的职责
→ H2「辨析」/「排查」
   → 逐条列举：现象 → 原因 → 结论，用 bullet 或 H3
→ 「注意」段（一两句风险提示，独立成段，无小标题）
→ （可选）H2「插件」/「推荐」，收尾给一个可用方案
```

要点：

- 开头绝不用「今天遇到一个问题」这类空话，而是直接给故障状态和它的异常之处。
- 大量使用「显然」「也就是说」「此时」来推进。
- 结尾常有戏谑：`32 on 1 是不存在的……`、`愉♂悦地设置起来吧~`。

## 三、Tips / 速查（LaTeX 114 篇，中位 2096 字）

两代写法：

**2013-2015（早期）**——极小化，直接给结构：

```
## 问题
### 环境         （一句话：XP sp3, TeX Live 2012, TeX studio.）
### 测试代码      （代码块）
## 原因/解决
（代码块 + 两三句解释）
```

**2016 之后**——先一句需求，再给代码，再给效果：

```
近日大概重拾了一点对 LaTeX 的兴趣，遇见这样一个问题：如何……？
→ H2 按解法分层（「缩印」「页码」「实际效果」）
→ 每层：朴素解法 → 它的问题 → 更进一步的解法（代码）→ 逐参数解释
→ 末尾贴效果截图
```

要点：**先给能跑的朴素解，再给精巧解**。这是这个站最稳定的叙事习惯——「以朴素的办法实现并不困难。不过，这样的做法扩展性太差……更有技巧的办法，需要深入到……」。

## 四、科普 /「谈谈 X」（Math / Econ / English / 乐理，60 余篇，中位 3000 字）

标题常用「谈谈 X」（29 篇），结构是**定义 → 分类 → 推导 → 分支 → 结论**，像数学证明。

```
「这是一个新的系列，讨论……」/「这是博弈论通俗演义的第二篇。我们首先分析 A，而后挖掘背后的模型，再引出 C。」
   ← 三段式预告，把全文路线一次说完
→ H2 概念 A
   → 一句话给出定义（短句，独立成段）
   → 拆成 2-3 个要素，每个一句
→ H2 推导
   → 「如果……那么……」「只要……就……」的条件推演
   → 中途必有一个反转小节，标题如「看似公平」
→ H2 结论/延伸
   → 用一句破折号总结：「于是，这是一件好事——贷款人、借款人、经济体加在一起赢了三次。」
→ 收在下篇的引子上：「这就引出了央行和中央政府的调控政策相关问题。」
```

要点：

- 数学公式一定 inline 且服务于推理，不炫技。
- 生活中的例子必须落在标题或首段（「为啥你炒股总亏」）。
- 口语化的例子 + 书面化的推导，两者交替。

## 五、读后感 / 赏析 / 杂谈（Literature / Life，14 篇，中位 1500 字）

两种子型：

**A. 摘录+短评型**（《谈人生》读后感）

```
交代读的什么、谁赠的（1-2 句）
→ 说明本文的编法（「这里同季先生选编文集一样，将这些摘录和感想选编在一起，形成此文。」）
→ 循环：引一段原文（用「」或缩进引用 + 出处）→ 一两句短评（可以只有一句、可以只有八个字）
→ 收束在一个被自己提炼出来的判断上（「真诚而不作伪是打动读者的「大杀器」，写文十年深以为然。」）
```

**B. 逐段拆解型**（《一篇关于大公司病的魔幻现实主义文章的读后感》，5986 字）

```
交代来源（知乎链接）→ 为什么值得写（「文章特别有意思，显得回味无穷。因此作此篇读后感。」）
→ H2 按原文段落推进（「初入江湖」「进入圈子」「深入试探」）
   → 每节：复述原文该段 → 「前面提到，文中的 X，隐喻的是 Y。」→ 展开自己的解读
→ 结尾落在自己的判断，不落在对原文的恭维
```

要点：**引原文一定标明出处**；短评允许极短（「季先生的文字还是有趣的。」）；不用「这本书告诉我们」这类总结腔。

## 六、资料整理 / Q&A（《百度大搜的一些历史经验》等，少量）

```
一句来源说明（「这是 2016 年 6 月和百度的技术专家交流的一些经验总结。近期翻出来，记录在这里。」）
→ H2「名词解释」（bullet 逐条）
→ H2 各主题（架构 / 发展历程，H3 按阶段：第一阶段、第二阶段……）
→ H2「问答环节」（Q：… / A：… 逐条）
→ H2「总结」（bullet 3-4 条）
```

这是**唯一常见「总结」章节的体裁**，因为素材本来就是别人讲的话，需要自己落一遍结论。

## 七、开头句式库（可直接套用）

| 类型 | 真实例句 |
| - | - |
| 动因式 | 「此篇我们通过逐步实现线程池，来探讨线程池中的关键技术。」 |
| 现象式 | 「某次 VSCode 升级之后，我从 macOS 连远端开发机的 Remote-SSH 突然进入了死循环」 |
| 提问式 | 「近日大概重拾了一点对 LaTeX 的兴趣，遇见这样一个问题：如何在 LaTeX 中实现缩印效果……？」 |
| 系列式 | 「这是博弈论通俗演义的第二篇。」/「这是一个新的系列，讨论桥桥水基金创始人 Ray Dalio 的经济学理论。」 |
| 由头式 | 「今天有人在群里讲，大意是「我就喜欢 CJK……」我对此的评价是「啥也不懂，瞎搞胡搞」。」 |
| 补白式 | 「越狱用户在将 iDevice 越狱后往往会接触到……但中文互联网圈子内似乎还没有对它们做完整解释的帖子，故有此篇。」 |

## 八、结尾方式库

| 方式 | 占比 | 例句 |
| - | - | - |
| 讲完就停（末句仍是技术内容） | ~50% | 「如果观察到程序稳定运行时 RES - SHR 不断增长，则可能预示着程序存在内存泄漏现象。」 |
| 一句判断收束 | ~25% | 「很明显，这样写起来可读性强很多。」 |
| 戏谑/口语收尾 | ~10% | 「愉♂悦地设置起来吧~」 |
| 显式总结章节 | 12% | 只见于资料整理型 |
| 指向下篇 | 少量系列文 | 「这就引出了央行和中央政府的调控政策相关问题。」 |
| 反问读者 | 极少（2 篇） | 「所以，你愿意开始坚持写博客了吗？」 |

**禁止**：以「希望对你有帮助」「欢迎留言讨论」「以上就是全部内容」结尾。全站 405 篇里零出现。

## 九、小标题命名法

- 名词短语，四到八字：「问题」「原理」「辨析」「前置知识」「实际效果」「基本用法」「安装字体」
- 文言单字：「跋」「引言」
- 允许口语：「实际操作看看」「举个栗子」「一次尝试」「看似公平」
- 禁用：「深度解析」「一文读懂」「你必须知道的」「终极指南」
