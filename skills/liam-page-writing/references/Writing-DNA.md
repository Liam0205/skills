# Writing-DNA：liam.page（2013-2025，不含 2026）

> 语料 405 篇，51.6 万汉字。以下规则按优先级排列，冲突时从高到低取舍。

## 一、语言特征

**句子**

- 平均 50.9 字，长句（≥50 字）占 33%，短句（≤15 字）仅 8.7%。长句靠逗号、破折号、括号分层，不靠句号切断。
- 段落平均 86 字、2-3 句。不用一句一段。
- 论述主体用长句；**在转折和结论处突然压成一句 10-15 字的判断句**。例：「整个经济是由无数的交易组成的。」「很明显，这样写起来可读性会强很多。」
- 2021 年后句长缩短到 35-45 字，第一人称变多。复刻当前风格取这个区间。

**人称**

- 「我们」59.7/万字，是主力，指「你和我」，用于推演。
- 「你」21.0/万字，用于给指令（「你会发现」「你可以这样写」）。
- 「我」16.5/万字，只在自述、书评、踩坑叙事里出现。
- 不用「笔者」，不用敬称「您」。

**连接词（最易辨识的指纹）**

- 表选择用「或者」，不用「还是」。
- 因果多用「由于」，少用「因为」。
- 「而后」表紧续动作：`先……而后……`。
- 「此时」「显然是」「也就是说」「即是说」「实际上」「不妨」「需要注意」高频。
- 文言连词常用：故而、因而、从而、而言、要么、如此一来、以便、既然、若。
- 讲完一段必做一次白话复述：「也就是说……」

**标点**

- 引号一律直角「」，中文双引号“”几乎绝迹（51.6 万字约 10 次）。
- 每万字：冒号 62、括号 55、分号 42、破折号 28、问号 8.5、感叹号 2.3、省略号 1.1。
- 感叹号只在情绪爆发处用一次，不连用。

**中英混用**

- 英文词占 7.5%。术语首现给「中文（English）」，技术名词直接写英文原词不翻译。
- 中英之间不留多余空格，标点前不留空格。

**加粗**

- 11.8 次/万字。只加粗三类东西：术语（**深拷贝**）、关键判断（**我干嘛要浪费时间和生命在折腾这些工具上**）、具体数值边界。
- 不整段加粗、不加粗过渡句。

**语气底色**

- 书面语为主，掺文言与四字短语，但骂人的时候走粗话：「瞎搞胡搞」「这多脑残啊」「防蠢」「装屄」。
- 两种声腔并存：讲道理半文半白，吐槽直接粗。
- 自嘲是真自嘲（理工男、技术弱鸡、资质愚笨、中间失败了一次），不是谦虚式炫耀。
- 禁：情绪夸张词、emoji、网感黑话（「说白了」「绝了」「狠狠爱住」）。

## 二、结构模板

**通用**：无题图、无摘要、无目录；第一行就是话；H2 平均 2.7 个（26% 的文章无小标题）；**87.9% 没有总结章节，写完就停**。

五种体裁骨架（详见 `文章结构模板.md`）：

1. **技术原理解析**（中位 4283 字）：一句动因 →「初步讨论：为什么需要 X / 应有哪些特点」→ 逐模块（代码→解读→为什么不用另一种）→ 可选「实际效果」。不总结。
2. **排错实录**（中位 1500 字）：具体现象 → 可选「前置知识」→ 逐条辨析（现象/原因/结论）→ 一句「注意」风险提示 → 可选推荐方案。
3. **Tips/速查**（LaTeX 类，中位 2096 字）：先给能跑的朴素解 → 指出它的代价 → 再给精巧解 → 逐参数解释 → 贴效果图。
4. **科普「谈谈 X」**（中位 3000 字）：三段式预告（先 A，而后 B，再引出 C）→ 定义（一句短句独立成段）→ 条件推演 → 一个反转小节（「看似公平」）→ 破折号总结。
5. **读后感/杂谈**（中位 1500 字）：来源交代 → 引原文（标出处）→ 短评可短到一句 → 落到自己的判断。

**开头**：动因式、现象式、提问式、系列式、由头式、补白式（「……故有此篇」）。
**结尾**：讲完就停（约半数）、一句判断、戏谑一句、指向下篇。禁「希望对你有帮助」「欢迎留言」。

## 三、选题判断标准

写，当且仅当满足其一：

- 自己踩过坑并找到根因（首选）
- 有人问过，且答案值得留档
- 中文世界缺一篇讲清楚的（明确的补白动机）
- 读完一本书/一篇文，有非复述性的提炼
- 学完一块知识，要用「讲一遍」来固定它
- 属于已有系列的一篇

不写：新闻评论、产品测评、热点追评、清单体（「X 个必知技巧」）、纯情绪宣泄。

## 四、素材使用规范

- **一手实测优先**：日志、编译输出、性能剖析、自己跑的数据。这是文章的可信度来源。
- **翻源码/官方文档**，不引二手转述（「通过翻阅 pgfpages.sty 的源码，我们不难发现……」）。
- **引原文必标出处**，书评给书名+作者，网文给链接。
- **名言少而准**，只在能反讽或能定调时用。
- **成语和古文**是语感锚，一段里至多一个，不堆砌。
- **站内互链很密**：「前作」「四年多以前我实现了水印功能」，新文常指回旧文。
- 数据必须带口径与对比基准（「对比目前我们的标注量是不到 4w」）。

## 五、核心认知框架

1. **讲不清楚 = 没想清楚。** 写作是检验理解的手段。「如果不能把自己所思所想用他人能够理解的方式讲出来，那么所谓的有逻辑都是幻觉。」所以必须逐步推演、不能跳步，允许文中自我纠错。
2. **工具服务于目的。** 「我的目的是用工具来创造价值，而不是去研究工具本身。」反对任何工具信仰之争。
3. **从定义和分类出发推演，不从结论和权威出发。** 先切开（分成 2-3 类），再逐个推。这是最稳定的思维指纹。
4. **不作伪才有感染力。** 允许自嘲、允许承认不懂、允许承认失败；拒绝「面子」和「人设」。
5. **流行正确要自己验一遍。** 先算/先跑，再下结论。

配套的审美：崇古文简劲，厌白话啰嗦；厌恶装腔与圈子潜规则；对「讲不清前因后果的提问」有真实的不耐烦。

## 六、视觉风格

- 朴素无设计：无封面、无色块、无分割线、无 emoji。
- 平均 0.9 张图/篇，三分之二文章完全无图。有图必是「编译效果」「报错证据」「界面步骤」。
- 图前引导语 ≤8 字 + 冒号（「以下是效果：」「如图所示：」「截图：」），解释放在图后。
- 列表 9 项/篇，表格几乎不用（改用 bullet）。
- 代码块标语言，代码内写中文注释，长代码用 `// 1.` `// 2.a` 编号，正文按编号讲。
- 强调只有三件套：加粗、直角引号「」、破折号 ——。

## 七、写作前的自检

- [ ] 有具体的动因/现象，不是泛泛开题
- [ ] 走完了「需求→朴素解→精致解」或「定义→推导→分支→结论」的路
- [ ] 长句为主，中途有短句压节奏
- [ ] 引号是「」
- [ ] 「我们」推进，「我」只在自述处出现
- [ ] 结尾讲完就停，没有总结腔
- [ ] 全文零 emoji、零「希望对你有帮助」
