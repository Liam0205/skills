# liam.page 写作风格

## 什么时候用

用户要求按下面任一种方式写作时使用：

- 「按我博客的文风写」「用 liam.page 的风格」
- 写中文技术长文、排错实录、LaTeX / 系统 / 编程教程
- 写数学、经济、乐理、语言类的科普（「谈谈 X」体）
- 写书评、读后感、古文赏析

不适用于：营销文案、新闻快讯、产品测评、短视频脚本。

## 写作前必读

两部分都要做完，只读产物就下笔会丢掉语感。

### 一、五份蒸馏产物

| 文件 | 提取什么 |
| - | - |
| `references/Writing-DNA.md` | 总体约束与优先级 |
| `references/语言DNA.md` | 高频词、句长分布、标点习惯、人称用法、中英混用 |
| `references/文章结构模板.md` | 本次体裁的骨架，开头与结尾句式库 |
| `references/写作视角与认知框架.md` | 切入角度、素材偏好、五条核心命题 |
| `references/视觉风格指南.md` | 配图位置与功能、加粗密度、代码块、段落节奏 |

### 二、5 篇同体裁原文

从 `samples/full/` 挑，`samples/index.json` 里有每篇的 `date`、`categories`、`chars`、`images`。

挑选顺序：

1. 先用 `categories` 过滤出体裁相同的
2. 候选超过 5 篇时，取 `date` 最近的 5 篇（近期更能代表当前风格）
3. 候选不足 5 篇时，用同体裁不同题材的补齐
4. `index.json` 不可用时，按文件名开头的日期和标题判断

读原文的目的不是找素材，是校准产物里描述不出来的东西：句子的呼吸感、段落之间怎么接、什么时候突然用一个短句。读完要能说出这 5 篇的共同语感，再动笔。

### 体裁对照

| 要写的 | 结构模板 | 主要取样区 |
| - | - | - |
| 技术原理解析 | 第一节 | `Algorithm and Computer Science`，2017-2022 |
| 排错实录 | 第二节 | `Computer Skills`、`Jailbreak and Reverse Engineering`，2022-2023 |
| Tips / 速查 | 第三节 | `LaTeX`，2016-2020 |
| 科普「谈谈 X」 | 第四节 | `Mathematics and Natural Sciences`、`Economics and Investment`，2018-2021 |
| 读后感 / 杂谈 | 第五节 | `Literature and Social Sciences`、`Life and Human Nature`，2016-2024 |

## 写作时的优先级

规则冲突时按此顺序取舍：

1. 用户的明确指令（题材、长度、平台、语言）
2. `文章结构模板.md` 中匹配当前体裁的那一套
3. `语言DNA.md` 与 `视觉风格指南.md`
4. `写作视角与认知框架.md`（决定立场和素材选择，不决定句式）

原文里的具体观点和事实不能搬进新文章。复刻的是写法，不是内容。

## 硬约束速查

- 引号一律直角「」，不用中文双引号“”
- 推演用「我们」，「我」只出现在自述、书评、踩坑叙事里；不用「笔者」，不用敬称「您」
- 平均句长 50 字上下，长句为主，转折处压成一句短判断
- 结尾讲完就停。不写总结章节，不写「希望对你有帮助」「欢迎留言」
- 加粗只落术语、关键判断、具体数值
- 配图 ≤1 张（教程类可多），图前引导语不超过八个字加冒号
- 代码块带语言标记，代码内注释用中文
- 零 emoji，零网络黑话
- 不追热点，不写清单体，不写产品测评
- 引论文、引他人文章，第一次出现就给可点击的链接，不要只写标题和编号

## 逐句审校

写完不等于完工。`less-ai-tone` 是白名单式改写，只处理它列出的十七类结构；下面五类它管不到，必须自己逐句过一遍。这一步排在去 AI 味之后、发布之前。

**一、不造奇怪的比喻**

抽象的过程不要用动作化、拟人化的说法去装点。「输入正被推着往长里走」「这套东西长出了自己的生态」这类句子读着有画面，实际什么都没说。直接讲事实：输入越来越长。

**二、不直译形容词**

英文里的 clean、solid、sharp、subtle 直译过来，在中文里都不自然。

| 别写 | 改写成 |
| - | - |
| 干净的形式 | 漂亮的形式、简洁的形式 |
| 差着一大截 | 相差很远 |
| 一个很强的信号 | 一个明显的信号 |
| 这套东西很锋利 | 这套东西很有效 |

判断办法：把那个形容词换成一个同义的中文口语词，若原句立刻变得别扭，说明它是从英文里搬过来的。

**三、含义要准确**

- 主语和对象不能错位。「item 被不同 query 反复打分」是错的——item 是被召回，而后与 query 分别做一次判断。
- 因果要给对。「既然被复用的是 item」不成立，query 也在复用；真正成立的是「item 会被反复计算」。
- 不要把数据集的统计特征说成设计意图。论文里 26 个 token 是人工评测集的平均值，不是论文的设计目标。

**四、不要把手段当成目的**

动笔前先写定一句「这篇要弄清楚什么」，全文每一节都该服务于那句话。若那句话是「判断这套方案能不能用、有哪些坑」，那么算力、存储、延迟都是论据，不能反过来变成文章的主题。一旦发现自己在「把成本算一遍」，就说明立意被手段替换了，要停下重写。

**五、引文首次出现给链接**

引论文、引他人文章，第一次出现就挂上可点击的链接。

## 写完之后

需要清 AI 痕迹时，读同仓的 `../less-ai-tone/SKILL.md`，按其中的编号规则逐条过一遍。这个 skill 一起装的情况下路径才有效；没有安装时跳过这一步，并直接说明跳过了。

清理时如果与本 DNA 冲突，以本 DNA 为准。比如去 AI 味规则倾向于压缩长句，而这份 DNA 的长句是作者的正常写法。

清完之后还要再走一遍上面的「逐句审校」。生造的比喻、直译的形容词、错位的因果、被手段替换的立意、缺失的引文链接，这五类问题都不在 `less-ai-tone` 的白名单里，它按规则不会碰，只能自己逐句看。

## 语料

`samples/full/` 收录 405 篇，时间跨 2013-01 至 2025-12，共 51.6 万汉字。每篇带 frontmatter（title / url / date / categories / tags），正文为 Markdown。

`samples/index.json` 是索引，字段：`file`、`date`、`title`、`categories`、`tags`、`chars`、`images`、`code_blocks`。

需要重新抓取或更新时：

```
python3 scripts/fetch_corpus.py --site https://liam.page --before 2026 --out ./samples
```

脚本依赖 `beautifulsoup4` 和 `lxml`。

## 已知局限

- DNA 只决定怎么写、怎么想，写不出作者没经历过的事。事实、数据、判断必须来自用户
- 2021 年后句长变短、第一人称变多。写「现在的他」用 2019-2024 的节奏，不要照抄 2013 年的超长句
- 语料里 78% 是技术类，生活与文学类样本少，那两类的模板置信度较低
