# liam.page 写作风格

## 什么时候用

用户要求按下面任一种方式写作时使用：

- 「按我博客的文风写」「用 liam.page 的风格」
- 写中文技术长文、排错实录、LaTeX / 系统 / 编程教程
- 写数学、经济、乐理、语言类的科普（「谈谈 X」体）
- 写书评、读后感、古文赏析

不适用于：营销文案、新闻快讯、产品测评、短视频脚本。

## 写作前必读

两部分都要做完，只读产物就下笔会丢掉语感。

### 一、五份蒸馏产物

| 文件 | 提取什么 |
| - | - |
| `references/Writing-DNA.md` | 总体约束与优先级 |
| `references/语言DNA.md` | 高频词、句长分布、标点习惯、人称用法、中英混用 |
| `references/文章结构模板.md` | 本次体裁的骨架，开头与结尾句式库 |
| `references/写作视角与认知框架.md` | 切入角度、素材偏好、五条核心命题 |
| `references/视觉风格指南.md` | 配图位置与功能、加粗密度、代码块、段落节奏 |

### 二、5 篇同体裁原文

从 `samples/full/` 挑，`samples/index.json` 里有每篇的 `date`、`categories`、`chars`、`images`。

挑选顺序：

1. 先用 `categories` 过滤出体裁相同的
2. 候选超过 5 篇时，取 `date` 最近的 5 篇（近期更能代表当前风格）
3. 候选不足 5 篇时，用同体裁不同题材的补齐
4. `index.json` 不可用时，按文件名开头的日期和标题判断

读原文的目的不是找素材，是校准产物里描述不出来的东西：句子的呼吸感、段落之间怎么接、什么时候突然用一个短句。读完要能说出这 5 篇的共同语感，再动笔。

### 体裁对照

| 要写的 | 结构模板 | 主要取样区 |
| - | - | - |
| 技术原理解析 | 第一节 | `Algorithm and Computer Science`，2017-2022 |
| 排错实录 | 第二节 | `Computer Skills`、`Jailbreak and Reverse Engineering`，2022-2023 |
| Tips / 速查 | 第三节 | `LaTeX`，2016-2020 |
| 科普「谈谈 X」 | 第四节 | `Mathematics and Natural Sciences`、`Economics and Investment`，2018-2021 |
| 读后感 / 杂谈 | 第五节 | `Literature and Social Sciences`、`Life and Human Nature`，2016-2024 |

## 写作时的优先级

规则冲突时按此顺序取舍：

1. 用户的明确指令（题材、长度、平台、语言）
2. `文章结构模板.md` 中匹配当前体裁的那一套
3. `语言DNA.md` 与 `视觉风格指南.md`
4. `写作视角与认知框架.md`（决定立场和素材选择，不决定句式）

原文里的具体观点和事实不能搬进新文章。复刻的是写法，不是内容。

## 硬约束速查

- 引号一律直角「」，不用中文双引号“”
- 推演用「我们」，「我」只出现在自述、书评、踩坑叙事里；不用「笔者」，不用敬称「您」
- 平均句长 50 字上下，长句为主，转折处压成一句短判断
- 结尾讲完就停。不写总结章节，不写「希望对你有帮助」「欢迎留言」。结论给完就收，不再补「回到标题那个问题」「代价在别处」「完美是相对的」这类收束段
- 章节标题与小节标题用名词短语，见下文「标题」
- 加粗只落术语、关键判断、具体数值
- 配图 ≤1 张（教程类可多），图前引导语不超过八个字加冒号
- 代码块带语言标记，代码内注释用中文
- 零 emoji，零网络黑话
- 不追热点，不写产品测评。「不写清单体」指的是不写以「X 个必知技巧」为全文结构的文章；正文里列举同质条目用列表是正常写法，见下文「列举」
- 破折号与分号按语料基线用：破折号 27.8/万字，分号 42.1/万字（数值见 `references/语言DNA.md`）。`less-ai-tone` 针对破折号那条，防的是 AI 拿它做揭晓式停顿，不是要求一个不用
- 引论文、引他人文章，第一次出现就给可点击的链接，不要只写标题和编号

## 标题

章节标题和小节标题只命名这一节讲的东西，不用对偶句，不用问句，也不把论点摆进标题。1083 个二级标题里，含逗号的占 1.7%，是问句的占 2.7%。

- ✅ 特定路径检测、异常代码检测、完整性检查、调度场算法、内存映射
- ❌ 文件藏得住，挂载藏不住／从镜像清单到代码字节／碎片与间隙里的真相

需要分层时可以加冒号，冒号右边仍然写名词短语：「其它防御手段：时序与退出机制」。

小节标题按内容命名。讲方案的写方案名（防守：动态库白名单、防守：检查关键函数的开头内容），讲动作的写动作（攻击：把越狱目录藏起来、攻击：改方法表）。不要写成一句判断（防守：清单只能证明「有东西进来了」）。

标题里写的动作要和正文对得上。标题写「攻击：抢在检测之前」而正文写的是「我们抢不过」，这一节就没有内容。

## 列举

并列三件以上、彼此同质的时候（检查项、威胁、可选方案、参数），改用列表，不要用分号串成一个长句。

- 标记用 `- `，一条一句。条目末尾的标点按它本身是不是完整句子决定：语料里 63% 以句号收尾，36% 不带标点。
- 列的是具体条目，不是一个论点。论点仍然写成段落。
- 引导语可以是一句完整的概述，也可以只有「例如说……」。
- 条目本身是问句的，带问号：「`/var/jb` 在不在？」

## 攻防与对比结构

写一攻一防、新旧两版对照这类成对推进的长文时，回合按实际发生的事划分，不预设每一轮都要有攻有防。

- 攻击方在这一轮没有可写的动作，就不要保留「攻击」小节。把对方的思路写进防守小节的第一句，交代完立刻说明为什么守得住。
- 同一轮里的第二条防守，用一句话直接承接，例如「还有另一种防守方案。」，不必补一个对应的攻击方。
- 一轮里的攻和防最好落在同一个目标上。不同目标各自发生过的事混进一轮，读者会以为它们在互相对打。
- 每节只写有记录的动作和结果。攻击没成功的，就写没成功；不要用另一款目标上的防守来填空。

## 逐句审校

写完不等于完工。`less-ai-tone` 是白名单式改写，只处理它列出的十七类结构；下面这些它管不到，必须自己逐句过一遍。这一步排在去 AI 味之后、发布之前。

**一、不造奇怪的比喻**

抽象的过程不要用动作化、拟人化的说法去装点。「输入正被推着往长里走」「这套东西长出了自己的生态」这类句子读着有画面，实际什么都没说。直接讲事实：输入越来越长。

**二、不直译形容词**

英文里的 clean、solid、sharp、subtle 直译过来，在中文里都不自然。

| 别写 | 改写成 |
| - | - |
| 干净的形式 | 漂亮的形式、简洁的形式 |
| 差着一大截 | 相差很远 |
| 一个很强的信号 | 一个明显的信号 |
| 这套东西很锋利 | 这套东西很有效 |

判断办法：把那个形容词换成一个同义的中文口语词，若原句立刻变得别扭，说明它是从英文里搬过来的。

**三、含义要准确**

- 主语和对象不能错位。「item 被不同 query 反复打分」是错的——item 是被召回，而后与 query 分别做一次判断。
- 因果要给对。「既然被复用的是 item」不成立，query 也在复用；真正成立的是「item 会被反复计算」。
- 不要把数据集的统计特征说成设计意图。论文里 26 个 token 是人工评测集的平均值，不是论文的设计目标。

**四、不要把手段当成目的**

动笔前先写定一句「这篇要弄清楚什么」，全文每一节都该服务于那句话。若那句话是「判断这套方案能不能用、有哪些坑」，那么算力、存储、延迟都是论据，不能反过来变成文章的主题。一旦发现自己在「把成本算一遍」，就说明立意被手段替换了，要停下重写。

**五、引文首次出现给链接**

引论文、引他人文章，第一次出现就挂上可点击的链接。

**六、不做残句**

这是最容易复发的一条。写技术文的中间地带，很容易滑成电报体：一个名词短语当判断（「载体只能是 KV。」），一个后缀当结论（「物理上只有 K/V 这一种载法」），一个数字当引证（「论文说大约十行代码。」），一个指示词裸着指代（「就是按这一集算的」）。单独看每句都通，连起来读是断的。

判断办法：把每句读一遍，问「这句的主语、对象、依据都交代了吗」。缺哪个补哪个。指示词（这、那、该、此）后面必须跟着明确的名词，不能只有量词。

**七、专有名词不意译**

原作里的术语沿用原作用词。prompt 就写 prompt，不要换成「指令」；token 不换成「词元」；gist token 就写 gist token。判断办法：把中文译法换回英文原词，若句子更准确，说明原来那个译法是自己造的。

**八、不过度比喻**

给普通判断加比喻是最容易上瘾的毛病。「代价落在三处」「它们指向同一个病灶」「三条路的毛病是同一个」，这三句说的分别是「有三点」「共性问题在于」「三种方案的共性问题在于」。比喻不增加信息，只增加阅读阻力。

判断办法：把比喻换成平实词，若信息没有减少，就换掉。常见需要还原的词：病灶、毛病、命门、卡脖子、落在 N 处、N 条路、拆开看。

**九、把独立分句断开**

一句话里用逗号串起两个都能独立成句的主谓结构，前面的逗号应当改成句号。高发位置在「不必」「因此」「但」「而」之前。

> ❌ 第二种是参数高效微调，不必全量重训，只学一小块参数，每个任务仍然要存一份权重。

> ✅ 第二种是参数高效微调，不必全量重训，只学一小块参数。每个任务仍然要存一份权重。

**十、说了几个就标几个**

写了「有三点」「有五件事」之后，下文必须显式标号，用「第一、第二、第三」或者「首先、其次、而后」，也可以直接用有序列表。只数不标，读者得自己数。

**十一、公式走 MathJax**

正文里的数学不要用 unicode 上下标凑（`d²`、`n_kv`、`k′`），frontmatter 设 `mathjax: true`，公式写成 `$...$` 与 `$$...$$`。两条实践约束：

- `$$ ... $$` 必须写在同一行。跨行写的话 markdown 渲染器会在中间插 `<br>`，MathJax 就认不出来了。
- 行内公式里的下标不要用裸下划线。`n_kv` 会被 markdown 当成斜体配对吃掉。改用不带下标的字母记号，或者先检查产物里有没有多出来的 `<em>`。

验证办法：`hexo g` 之后看产物里有没有 `tex-mml-chtml.js` 和 `has-jax`，再确认 `$$` 之间没有被塞进 `<br>`。

**十二、交稿前按关键词搜一遍**

下面这些词是 `less-ai-tone` 里最容易违规的三条的触发标记，写完之后直接搜，搜到就改：

- 翻案腔（第 1 条）：不是……而是、不在……而在、并非……而是、与其说
- 路径隐喻（第 13 条）：这条路、几段路、走一遍、三条路、两个点
- 财经隐喻（第 12 条）：账、算账、回本、记在谁头上

**十三、每个具体事实都要指得出来源**

机构、数字、时间、因果链条，只能来自你读过的代码、跑过的实验或用户给的材料。指不出出处的一律删掉，只保留现有材料撑得住的部分。写「群控和批量注册长期盘踞在越狱设备上，羊毛套利、盗刷与洗钱也大多以它为基础」，如果这几条没有本地材料，就压缩成能站住的那一句。

同一个道理也适用于因果推断。实验只证明「A 之后 B 消失」，就不要写成「A 导致 B 消失」；能够写出的，是哪几个候选解释还没有被排除。

**十四、没有可写的动作就不要编一个**

给一章安排「攻击—防守」的小节时，先问攻击方在这一轮实际做了什么。没做过的动作不要补，没查清的原因不要填。读者拿走的是确认过的事实和还没排除的候选，不是一段读起来顺的因果。

## 写完之后

需要清 AI 痕迹时，读同仓的 `../less-ai-tone/SKILL.md`，按其中的编号规则逐条过一遍。这个 skill 一起装的情况下路径才有效；没有安装时跳过这一步，并直接说明跳过了。

清理时如果与本 DNA 冲突，以本 DNA 为准。比如去 AI 味规则倾向于压缩长句，而这份 DNA 的长句是作者的正常写法。

清完之后还要再走一遍上面的「逐句审校」。生造的比喻、直译的形容词、错位的因果、被手段替换的立意、缺失的引文链接、指不出来源的事实，这些问题都不在 `less-ai-tone` 的白名单里，它按规则不会碰，只能自己逐句看。

## 语料

`samples/full/` 收录 405 篇，时间跨 2013-01 至 2025-12，共 51.6 万汉字。每篇带 frontmatter（title / url / date / categories / tags），正文为 Markdown。

`samples/index.json` 是索引，字段：`file`、`date`、`title`、`categories`、`tags`、`chars`、`images`、`code_blocks`。

需要重新抓取或更新时：

```
python3 scripts/fetch_corpus.py --site https://liam.page --before 2026 --out ./samples
```

脚本依赖 `beautifulsoup4` 和 `lxml`。

## 已知局限

- DNA 只决定怎么写、怎么想，写不出作者没经历过的事。事实、数据、判断必须来自用户
- 2021 年后句长变短、第一人称变多。写「现在的他」用 2019-2024 的节奏，不要照抄 2013 年的超长句
- 语料里 78% 是技术类，生活与文学类样本少，那两类的模板置信度较低
