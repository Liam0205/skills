# 2026-10 gist 长文返工实录

一篇按 liam.page 文风写的技术长文（约 3500 字），发表到 Hexo 博客。连续被打了四轮，最后一轮的原话是「写的太烂了。我真的崩溃」。这篇记录每一轮被指出的原句和改法，返工前先看一遍比读规则省时间。

## 第一轮：内容与措辞

| 被指出的原句 | 问题 | 改法 |
| - | - | - |
| 输入正被推着往长里走 | 生造比喻，读着有画面但什么都没说 | 输入越来越长 |
| 同一批 item 要被不同的 query 反复打分 | 事实错位 | item 会在不同 query 下被反复召回，与不同的 query 分别做一次判断 |
| 既然被复用的是 item | 因果不成立，query 也在复用 | 既然 item 会被反复计算 |
| 这个想法在论文里有个干净的形式 | 翻译腔，clean 直译 | 漂亮的形式 |
| 都与我们这里差着一大截 | 生造搭配 | 相差很远 |
| 但那套形式是为平均 26 个 token 的指令设计的 | 把数据集统计特征说成设计意图 | 训练集平均 20 个 token，人工评测集平均 26 个；26 倍压缩比是拿人工评测集算的 |
| 指令 | 术语错 | prompt |
| 此篇我们把这项成本拆开算一遍 | 立意被手段顶替 | 改成判断可行性、指出会出问题的地方 |
| 论文标题只有文字 | 缺链接 | 做成超链接指向 arXiv 摘要页 |

用户当时的判词：「这说明你写完后没有仔细审查。skill 里有吗？如果没有要求，那就补上。」

## 第二轮：人称跑了

统计出来「我们」11.2/万字，「你」2.8/万字，而 DNA 基线是 59.7 和 21.0。全文是无人称的推演口吻，像内部技术备忘。

改法是把每个推演节点交回「我们」：「此时我们自然想到」「我们第一个要确认的是」「我们不妨把……写出来」「所以我们自己算一遍」。补完是 43.5 和 13.6。

**教训**：这一轮是照指标刷出来的，数字上去了，气没上去——所以第四轮还是被判烂。指标能发现偏差，修不好文章。

## 第三轮：残句与公式

| 被指出的原句 | 问题 |
| - | - |
| 就是按这一集算的 | 指示词悬空，前面没交代是哪一集 |
| 搜索、推荐的相关性判断 | 推荐里没有「相关性判断」这个说法 |
| 载体只能是 KV。 | 突兀，没有铺垫就抛术语 |
| 物理上只有 K/V 这一种载法 | 电报体，省掉了主语和展开 |
| 论文说大约十行代码。 | 数字当引证，出处交代不清 |
| 全文用 unicode 上下标 | MathJax 没开，`d²`、`n_kv` 这类符号难看 |

用户当时的反应：「又开始省 token 了是吧？能不能行了？」「这完全不是我的写作风格。」

公式侧记下的两个坑：`$$ … $$` 必须写在同一行（跨行会被渲染器插 `<br>`）；行内公式里的裸下划线会被 markdown 当斜体配对吃掉，所以记号改成不带下标的字母。

## 第四轮：整体判死

「写的太烂了。我真的崩溃。」

这一轮没有具体句子的指摘，是对生产方式的否决。诊断：前四轮都在打补丁，每一轮修掉被指出的症状、制造新的不协调，文章成了七个补丁摞起来的产物。骨架先定死、内容后填，气从一开始就断了。

## 三条可复用的结论

1. **第一轮就该重写，不是改。** 第一轮暴露的是内容准确性和立意问题，改措辞救不回来。
2. **不要用指标自证合格。** 人称密度、句长、破折号频次，全部达标仍然可以是死文章。
3. **出声读一遍能拦掉一半。** 第三轮那些残句，读出声立刻别扭；靠眼睛扫和靠脚本统计都发现不了。
