# 按风格写作：生产过程

风格规则由别的 skill 提供——`writing-dna` 负责蒸馏，`liam-page-writing` 是 liam.page 那一套的具体规则，`less-ai-tone` 负责去 AI 味。**本 skill 管的是另一件事：怎么把这些规则变成一篇活的东西。** 两者同时加载，规则归它们，流程归这里。

## When to Load

- 用户要求「按某某的文风写」「用我的风格」「照这个 DNA 写」
- 上一稿被指摘语言问题，需要返工时
- 交付任何长文（>2000 字）之前，作为最后一个关口

不适用：短文案、邮件、即时回复。那些没有「通篇的气」这回事。

## 核心失败模式：把 DNA 当验收清单

按 DNA 逐项核对——句长落在区间、人称密度达标、直角引号、破折号频次、审校七条全过——稿子仍然是死的。

因为这些指标是**结果**，不是**原因**。一个人把一件事讲清楚的时候，那些数字自己会长出来；反过来照数字填句子，得到的是一篇每一条都合格、连起来读是断的文章。

指标只能用来事后发现偏差。看到「我们」只有 11/万字（基线 59.7），结论是口吻跑掉了，去改口吻；**不要为了把数字刷回去而往句首塞「我们」**。那是拿指标倒推句子，等于用第二种方式再犯一次同样的错。

判断办法：一篇好文章删掉所有风格标记之后，仍然是一篇能读的文章。如果你的稿子删掉标记就散架，说明骨架本来就是标记。

## 三个具体的错法

1. **先套骨架再填内容。** 选中「技术原理解析」这类模板，把 H2/H3 摆好再往格子里填，内容必然变成填充物。顺序要反过来：先想清楚这篇到底要说什么，结构从内容里长出来。骨架是事后总结的规律，不是事前的模具。
2. **从「介绍 X」写起。** 交代背景、介绍概念、解释术语，是最省力也最没意思的开头。从这件事里最别扭、最反直觉、最让人不放心的地方写起。读者留下不是因为你先介绍了背景，是因为第一句就有个真问题。
3. **一轮一轮打补丁。** 用户指出五处，就改那五处，下一轮又冒出五处；改到第三轮，文章已经是七个补丁摞起来的。补丁能修掉被指出的症状，修不了生产方式。

## 止损纪律

**连续两轮被指摘到语言层面（措辞、比喻、句法、语气），就推倒重写，不要继续补。**

这不是情绪判断，是成本判断：第三轮之后每改一处都会制造两处新的不协调，因为局部最优拼不出全局协调。重写的成本是确定的，补丁的成本是发散的。

推倒重写要换生产方式，不是换措辞：
- 换切入点（从最别扭的地方起笔，而不是从概念介绍起笔）
- 换顺序（先写论证，再决定分几节，最后才排标题）
- 不参考上一稿的句子，只参考它的结论

**不要把工作退给作者。** 被打回几轮之后，最容易滑向「你写，我只挑错」。这不是分工调整，是把活退回去——用户要的是成品，被打回之后反过来要求他动笔，等于告诉他这活干不了，多半会直接激怒他。写不顺就换粒度（一次一节）、换取证方式（出声读、逐条核）、换切入点，唯独不能换角色。

**对齐一次就够。** 动笔前把结构和立意讲清楚，拿到一次确认就往下走；每写完一节再问一遍「这样行不行」，会把耐心耗在确认上。他要看的是稿子，不是方案。

## 交付节奏

止损纪律的前提是「早发现」。发现得越晚，推倒重写越贵，所以节奏本身要设计。

**一次不要交全稿。** 先交一节，六百到九百字，让作者确认语感。语感不对，一节就够暴露，改一节也比改全篇便宜。整篇交出去再逐句返工，作者要读七八遍，工作量翻几倍，耐心也是有限的。前半讲清楚、后半做判断这类长文，天然就该分成两次交付。

**作者指出一类措辞问题，先在全文搜同类、一次改完。** 他说「这一集是哪一集」，全文里所有悬空的指代都要查；他说「不要过度比喻」，全文的比喻都要过一遍。只改被点到的那一句，下一句同样的病根会立刻被抓出来——等于把审校成本原样退还给作者，而且显得没在听。

**返工的最小单位是「节」，不是「句」。** 一节之内可以随便改；一节改到第三遍还不对，这一节重写。跨节打补丁是最坏的一种，因为相邻两节的语气会不一致。

## 交出去之前

四件事，缺一不可，另加一条纪律。

1. **出声读一遍。** 读着别扭的地方就是残句、直译词、断掉的气。这些任何指标都查不出来。
2. **说一句「这篇要弄清楚什么」。** 说不出来，或者说了但各节都不服务于它，停下重写。
3. **检查立意有没有被手段顶替。** 想讨论「这套方案能不能用」，写成「把成本算一遍」，就是顶替。这是最常见的一种跑偏，因为「算一遍」做起来省力、看起来有内容。
4. **逐句查主语、对象、依据。** 「载体只能是 KV。」缺主语和铺垫；「论文说大约十行代码。」缺出处交代；「就是按这一集算的」指代悬空。缺哪个补哪个，不要指望读者从上一句接。

纪律：**不要用「我检查过了」代替检查。** 说查过，就要拿得出证据——哪一条规则、命中还是没命中、落在哪一句。拿不出，就是没查。这条是整篇文档能不能落地的分水岭：规则写得再细，只要交稿时用一句「我核过了」就把它换掉，等于没写。

## 素材要求

按某人文风写作前，语料必须读够。蒸馏产物（DNA、语言 DNA、结构模板）只能校准指标，校不准语感。

- 通读同体裁原文，数量按来源 skill 的要求，**读不全就不许动笔**
- 读完要能回答一句：这几篇合起来是什么声音？答不出来说明没读进去
- 只读三篇、或某篇只读了前半，写出来的通篇口吻会跑掉——这不会在读的时候被发现，只会在被指摘的时候被发现

## 与去 AI 味工具的分工

`less-ai-tone` 是白名单式改写，只处理它列出的结构。它不管：

- 生造的比喻（「输入正被推着往长里走」）
- 直译的形容词（clean → 「干净的形式」，中文该说「漂亮的形式」）
- 专有名词意译（prompt 写成「指令」，token 写成「词元」；沿用原作用词）
- 过度比喻（「代价落在三处」「它们指向同一个病灶」「三条路的毛病是同一个」——说的都是「有三点」「共性问题在于」「三种方案的共性问题在于」。比喻不增加信息，只增加阻力）
- 节标题的英文直译（「它怎么做」「它做到什么程度」；中文写「具体做法」「效果评估」「要解决的问题」）
- 说了几点却不标号（「有五点值得注意」后面必须第一第二第三，或者直接用有序列表）
- 用逗号把两个能独立成句的主谓结构串成一句（高发在「不必」「因此」「但」之前）
- 错位的因果和对象（「item 被不同 query 反复打分」；实际是 item 被召回，再与 query 分别判断）
- 被手段顶替的立意
- 缺失的引文链接
- 残句与电报体

这几类只能自己逐句过。它们恰恰是最影响「像不像人写的」的部分。

## 案例

`references/2026-10-gist长文返工实录.md` 是一篇长文被连续打回四轮的完整记录，含每一轮被指出的原句和改法。返工前先读它，比读规则省时间。

`references/论文精读与落地判断.md` 是「读论文 + 讲给同事 + 判断能否用于自己场景」这一类文章的前后两半骨架，后半最容易写错的六个技术判断（参照系、缓存位置编码、单位置容量、讨论结论必须进稿等），以及这类文章最容易写错的五处（把数据集统计量当设计目标、收益数字不交代参照系、只报结果不报对照组的意义、略过论文没做的事、前半写成综述）。写这一类之前先看它。

`references/成稿交付-Hexo与Gist.md` 是最后一公里：liam.page 的 MathJax 写法与两个渲染坑、插图路径与中文字体、怎么撤稿，以及把草稿发成 secret gist 的接口用法。稿子定稿之后再翻。
